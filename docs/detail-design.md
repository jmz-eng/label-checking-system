# 详细设计说明书

## 1. 后端包结构

```text
backend/src/main/java/com/tagmanagement/
  common/        # 统一响应、异常、分页对象
  config/        # Web、跨域、拦截器配置
  controller/    # RESTful 接口
  dto/           # 请求和响应对象
  entity/        # 数据库实体
  mapper/        # MyBatis-Plus Mapper
  security/      # 登录令牌、权限注解、上下文
  service/       # 业务服务
  service/impl/  # 服务实现
```

## 2. 前端目录结构

```text
frontend/src/
  api/          # 接口请求封装
  assets/       # 静态资源
  components/   # 复用组件
  hooks/        # 自定义 Hook
  pages/        # 页面
  router/       # 路由与权限控制
  stores/       # 登录态与权限状态
  types/        # TypeScript 类型
  utils/        # 工具函数
```

## 3. 登录认证设计

1. 用户提交账号和密码。
2. 后端根据用户名查询用户。
3. BCrypt 校验密码。
4. 校验成功后生成访问令牌，令牌中包含用户 ID、用户名、过期时间。
5. 前端保存令牌，并在后续请求头中携带：

```text
Authorization: Bearer <token>
```

## 4. 权限校验设计

后端通过 `@RequirePermission` 标注接口权限：

```java
@RequirePermission("sample:verify")
```

拦截器处理逻辑：

1. 放行登录、健康检查、预检请求。
2. 读取 `Authorization` 请求头。
3. 校验令牌签名和过期时间。
4. 查询当前用户权限。
5. 判断接口所需权限是否存在。
6. 权限不足返回 `403`，未登录返回 `401`。

## 5. 标签编码规则

`labelCode` 由系统生成，不允许人工手敲：

```text
TM-{projectCode}-{animalNo}-{timePoint}-{sequence}
```

示例：

```text
TM-SN26007PK02-31211PK-D196H-0001
```

编码处理规则：

- 去除空格和特殊符号。
- 全部转为大写。
- 同一任务只允许一个有效 `labelCode`。
- `labelCode` 在数据库中唯一。

## 6. 扫码绑定规则

输入：

- `labelCode`
- `animalNo`

校验：

- 标签码必须存在。
- 任务状态必须为已打印或待绑定。
- 传入动物号必须与任务动物号一致。

处理：

- 通过：任务状态改为已绑定，写入成功扫码记录。
- 失败：任务状态不变，写入失败扫码记录。

## 7. 操作核对规则

输入：

- `labelCode`
- `projectCode`
- `animalNo`
- `timePoint`

校验：

- 项目号一致。
- 动物号一致。
- 时间点一致。
- 任务不能已作废。

处理：

- 通过：任务状态改为已核对。
- 失败：返回差异字段，例如“时间点不一致，期望 D1-96h，实际 D1-24h”。

## 8. 录入确认规则

输入：

- `labelCode`
- `resultNote`

校验：

- 任务必须已绑定或已核对。
- 已作废任务不能录入。

处理：

- 更新任务状态为已录入。
- 写入扫码记录和审计日志。

## 9. 异常处理

| 场景 | 返回码 | 说明 |
|---|---:|---|
| 未登录或令牌失效 | 401 | 请重新登录 |
| 权限不足 | 403 | 当前账号无权执行该操作 |
| 参数错误 | 400 | 返回具体字段错误 |
| 业务冲突 | 409 | 如重复项目编号、重复标签 |
| 系统异常 | 500 | 返回友好提示，不暴露堆栈 |

## 10. 审计日志

记录字段：

- 操作人
- 模块
- 操作类型
- 业务主键
- 操作详情
- 操作时间

审计日志用于监管核查、客户审计和异常回溯，不允许普通技术员删除。

## 11. 用户管理规则

- 用户列表支持按用户名、姓名和部门搜索，不返回密码哈希。
- 新增用户时用户名必须唯一，初始密码至少 8 位，至少分配一个有效角色。
- 用户名创建后不可修改，避免审计记录和业务关联失真。
- 编辑用户采用事务同时更新用户资料和用户角色关系。
- 当前登录用户不能停用自己或修改自己的角色，防止管理员误操作导致权限立即丢失。
- 重置密码采用独立权限 `user:reset-password`，密码只写入 BCrypt 哈希。
- 新增、编辑和重置密码均写入审计日志，审计日志不记录明文密码。
