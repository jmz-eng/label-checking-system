# 实验工作区使用说明

从左侧“实验列表”创建或选择试验。所有资料、管子、扫码和追溯均在所选试验下操作。带“旧版”的菜单保留原有任务和历史；系统管理仍维护用户及权限。

## 准备资料

1. 在“用途配对”设置采血/分装关键词并确认用途规则，例如PK、血常规。关键词只作建议，导入时仍须确认。
2. “附件导入”下载对应模板，上传并检查逐行预览。分组表固定三列：`试验编号、动物号、芯片号`；两张管表固定五列：`试验编号、动物号、时间点、管标信息、采样日期`。保留完整管标信息；采样日期均指原始采血日期。
3. 确认每支管用途，分装管选择具体来源采血管；有歧义时手工或批量指定。重复文件/行需要明确确认追加，不自动合并实际管子。表格问题按工作表、行、列提示，修正后再导入。
4. 分组关系、管子列表可补充少量记录并更正或停用/作废。更正填写原因；修改管子产生新身份及条形码，旧码作废。仅补打时保留原码。

## 核对

进入对应核对页，先选采样日期、时间点及本次用途。扫描框接受扫码枪输入，也可粘贴码后按回车。

- **采血核对**：扫动物芯片，再扫采血管。按最新有效分组关系核对动物，同时核对试验、日期、时间点与用途。
- **血样处理核对**：扫具体来源采血管，再扫分装管。来源必须已有该支管的成功采血核对记录；可保留来源继续下一支分装管。
- **失败处理**：换正确管重扫，或填写原因并明确异常结束。异常结束不等于通过。刷新或切换页面不能绕过未解决的失败。
- **换条件**：通过或尚未失败时，使用“重新选择采样条件”；失败轮先纠正或异常结束。
- **结果未确认**：网络中断或保存尚未确认时，使用页面提供的原操作重试。系统不会以本地匹配代替已保存的成功结果。

多人分别登录各自账号，可在同一试验操作不同动物。每条记录保留实际操作账号与服务器保存时间。

## 标签与追溯

“标签打印”选择管子后显示完整五字段预览，逐张分页。标签25×10毫米，上方固定12位数字CODE128条形码，下方原始字段；动物号与时间点合为一行，五项信息均保留。过长内容阻止打印并提示；不要靠缩放裁切绕过。扫码后由系统查出完整样品信息。Excel仍为原有五列，不需要技术员填写条码。旧二维码仍可核对，作废状态对两种扫码身份同样生效。

登记打印请求及打开打印窗口不代表纸张已成功打印。条形码图像解码、浏览器PDF检查不能替代打印机、标签纸、扫码枪的实物验证。得力14881S为激光一维扫码器，不支持屏幕码，须打印纸质标签试扫；具体步骤见[条形码标签说明](barcode-labels.md)。

“核对记录”支持筛选及导出，失败、纠正通过、异常结束分别保留。详情展示当时的预期条件、实际管子和映射版本；“更改记录”展示更改前后及原因。新核对使用最新有效资料，旧记录不会随资料更正而改写。

## 本地开发验证

启动方式见仓库README；请使用独立测试数据库及模拟数据。不要将本机预览库或私有配置提交到仓库。后端测试命令为`mvn test`；前端为`npm run lint`、`npm run build`、`npm test`。前端浏览器测试使用独立5175端口和接口模拟数据，真实浏览器连接真实后端的验收另行记录。

已在独立本机MySQL验证建表/迁移和主要核对及并发行为。生产升级、硬件打印及正式数据验收仍需单独安排。当前分支没有服务器部署操作。
