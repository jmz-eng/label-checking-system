# 条形码替换 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 所有标签打印改为清晰的小尺寸条形码，兼容既有扫码身份与审计。

**Architecture:** 后端增加共用的持久化数字别名登记表及 barcode 服务；实验管和旧任务响应附加 barcode，扫码通过别名恢复原实体。前端共用 CODE128 C 渲染及 25×10 mm 布局函数，两个标签组件共用规则。

**Tech Stack:** Java 17/Spring Boot/JdbcTemplate/MySQL 8/H2，React/TypeScript/SVG，JsBarcode（官方实现），JUnit/Playwright。

## Global Constraints

- Only label-checking-system; no medicine-reminder changes and no server deployment.
- 25×10 mm; 300 dpi; CODE128 C; fixed 12-digit persistent globally unique barcode per physical tube/task.
- Barcode narrow module at least 2 printer dots; left/right quiet zone at least 10 modules; text minimum 16 printer dots; preserve all fields or block printing with clear error.
- Preserve original codes, immutable histories, repeat-print identity and new identity for replacements; both old/new scans obey existing validation and audit rules.

### Task 1: Barcode registry, all label renderers and regression coverage

**Files:** backend registry/service/migration, ExperimentRepository/SessionService/DataService as needed, SampleTaskService/Response; frontend label layout utilities/components/types and related Chinese copy; backend and frontend tests.

**Interfaces:** Existing code/labelCode stays unchanged. Tube and SampleTask responses add `barcode: string`, containing exactly 12 decimal digits. Frontend prints barcode only; it must not synthesize an alias from code/id. Backend accepts either registered barcode or existing original code in existing scan endpoints.
